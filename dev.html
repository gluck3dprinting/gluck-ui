저장소·토큰·배포·변경 절차

디자인 시스템을 유지·배포하는 사람을 위한 문서입니다. 컴포넌트를 가져다 쓰는 방법은 디자인 시스템 › 내 시스템에 적용하기에 있습니다.

SECTION 00

저장소 구조

github.com/gluck3dprinting/gluck-ui · main에 push하면 GitHub Actions가 Pages로 자동 배포합니다.

gluck-ui/
├─ tokens/gluck.tokens.json   ★ 값의 원본 (W3C DTCG). 손으로 편집하는 유일한 값 파일
├─ dist/
│  ├─ gluck-tokens.css          :root 시맨틱 변수 + [data-theme="dark"] + [data-theme="admin"]
│  └─ gluck.css                 fonts + tokens + base(a11y) + components + utilities — 제품이 link하는 한 파일
├─ assets/
│  ├─ logo/                     워드마크·심볼·파비콘 (brand-resource-center 원본 미러)
│  └─ icons/icons.svg           Lucide 스프라이트 46종 + 로고 <symbol>
├─ docs/docs.css · docs.js      문서 페이지 전용 크롬 — 배포 대상 아님
├─ index.html · dev.html        디자인 시스템 페이지 · 이 문서 (둘 다 dist/gluck.css의 소비자)
├─ .github/workflows/
│  ├─ pages.yml                 main push → Pages 배포
│  └─ design-lint.yml           금지 문자열 · HEX 리터럴 검사 (다른 저장소에서 재사용 가능)
├─ README.md · CHANGELOG.md
└─ .nojekyll
dist/는 생성물입니다. 값을 바꿀 때는 tokens/gluck.tokens.json을 수정하고 dist/gluck-tokens.css를 맞춥니다 (빌드 스크립트는 다음 단계 — 그전까지 수동 동기화). 컴포넌트 CSS(dist/gluck.css)에는 HEX 리터럴을 쓰지 않고 시맨틱 변수만 참조합니다.
SECTION 01

토큰 계층 · 네이밍

3계층입니다. 컴포넌트와 제품 코드는 2계층(시맨틱)만 참조합니다. 테마는 시맨틱 값만 재바인딩하므로 컴포넌트 CSS는 한 벌입니다.

계층접두어 · 예규칙
1. Primitive--gluck-blue-600 · --gluck-gray-300 · --gluck-red-700원시 팔레트. 숫자 스케일(밝음 100 → 어두움 900). 컴포넌트에서 직접 참조 금지 — 예외: 소셜 로그인 3p 색, 로고 컬러웨이 데모
2. Semantic--color-{역할}-{변형} · --space-4 · --radius-md · --shadow-md · --z-modal · --duration-base · --font-h2 · --size-control-md역할 이름. 색은 bg · text · border · action · status · focus-ring 그룹. 제품·컴포넌트는 이 계층만 사용
3. Theme[data-theme="dark"] · [data-theme="admin"]시맨틱 값만 덮어씀. 어느 요소에나 붙일 수 있어 다크 페이지 안에 라이트/관리자 영역을 만들 수 있음. 라이트 기본값은 :root, [data-theme="light"], [data-theme="admin"]에 선언되어 있어 서브트리에서도 완전한 세트를 받음

테마 동작 규칙

/* 페이지 전체 */
<html data-theme="admin">            ← 운영 툴: 라이트 고정
<html>                              ← 생략: 라이트 + OS 다크 자동 (prefers-color-scheme)
<html data-theme="light">            ← OS 설정과 무관하게 라이트 고정

/* 서브트리 — 다크 페이지 안의 라이트 카드 */
<div data-theme="light">…</div>

/* 반응형 재바인딩 (토큰 파일 안) */
@media (max-width: 1279px) { :root { --gutter: 20px; } }
@media (max-width: 767px)  { :root { --font-size-display: 40px; --section-y: 64px; … } }

내 CSS에서 토큰 쓰기

이렇게

.my-panel {
  background: var(--color-bg-surface);
  border: 1px solid var(--color-border-default);
  border-radius: var(--radius-lg);
  padding: var(--space-6);
  color: var(--color-text-secondary);
}
.my-brand { --brand: var(--color-action-primary); }

이러면 안 돼요

.my-panel {
  background: #FFFFFF;              /* HEX 직접 — 테마 전환 안 됨 */
  border-color: var(--gluck-gray-100); /* 원시 토큰 직접 참조 */
  border-radius: 10px;              /* 스케일 밖 값 */
  font-family: Pretendard;           /* 서체는 SUIT 단일 */
}

시맨틱 토큰 — 테마별 실시간 값

같은 토큰 이름이 테마마다 어떤 값으로 해석되는지 — 이 페이지에 로드된 CSS 변수에서 실시간으로 읽습니다. 우상단 다크 모드 버튼을 누르면 왼쪽 열이 바뀝니다.

SECTION 02

배포 · 버전

main에 push하면 1~2분 뒤 Pages에 반영됩니다. 제품은 "최신"(Pages) 또는 "고정"(jsDelivr 태그) 중 하나를 선택합니다.

파비콘 · 로고 · 아이콘…/assets/logo/GLUCK_Favicon.ico · …/assets/logo/GLUCK_Wordmark_currentColor.svg · …/assets/icons/icons.svg
AI 코딩 도구용 참조https://gluck3dprinting.github.io/gluck-ui/llms.txt — 규칙·클래스·토큰·아이콘 id 전체. 프로젝트 CLAUDE.md에서 이 파일을 읽도록 지시. 컴포넌트·토큰을 바꾸면 이 파일도 함께 갱신

SECTION 03

변경 절차 · 자동 검사

값은 tokens/gluck.tokens.json 한 곳에서만 바꾸고, 규칙은 사람의 기억이 아니라 CI가 지킵니다.

값이 흐르는 경로

tokens/gluck.tokens.json손으로 편집하는 유일한 값 파일
dist/gluck-tokens.css · gluck.css (JSON에서 생성 — 현재 수동 동기화)
GitHub Pages · 태그gluck3dprinting.github.io/gluck-ui · jsDelivr @태그
각 시스템홈페이지 · 견적 · 채용 · 브로슈어 · Madmin · Hermes
CI 검사아래 표 — 저장소에 push할 때마다 자동

자동 검사 (.github/workflows/design-lint.yml)

검사스크립트실패 조건
HEX 리터럴 구현design-lint.ymldist/·tokens/ 밖에서 #RRGGBB 발견 시 경고 (허용: data:image, 문서 코드블록)
토큰 계약 예정check-tokens문서·HTML에 쓰인 --* 이름이 dist에 미선언
대비 예정contrast텍스트 역할 토큰 < 4.5:1 · 비텍스트 < 3:1 (디자인 시스템 페이지 §02 표와 같은 계산)
금지 문자열 구현design-lint.ymlgluck.co.kr · customer@gluck · hr@gluck · JetBrains · Pretendard
접근성 예정pa11ycolor-contrast · label · button-name · html-has-lang

규칙을 설명하느라 금지 문자열이 등장하는 줄에는 <!-- lint-ignore --> 주석을 붙이면 검사에서 제외됩니다.

# 다른 저장소에서 같은 검사 재사용 — .github/workflows/lint.yml
jobs:
  lint:
    uses: gluck3dprinting/gluck-ui/.github/workflows/design-lint.yml@main

PR 체크리스트 (컴포넌트·토큰 변경 시)

  • 1 변경 유형: Type A 토큰 값 · B 컴포넌트 · C 신규 · D 문서 · E 긴급 패치
  • 2 tokens.json만 수정했고 dist/는 빌드 산출물인가
  • 3 새 색이 있다면 대비표(디자인 시스템 §02)에 행을 추가했고 AA를 통과하는가
  • 4 라이트·다크·admin 3테마에서 렌더를 확인했는가
  • 5 키보드만으로 조작 가능한가 (focus-visible · ESC · Tab 순서)
  • 6 CHANGELOG.md에 항목을 추가했고 버전(semver)을 올렸는가
  • 7 영향받는 형제 저장소를 체크했는가 (BRC · quote · recruit · openfactory · brochure · admin)

변경 절차

  • 브랜드 확정 → 같은 주 DS 패치·태그 (SLA)
  • 이슈 템플릿 → PR(리뷰 1인) → CI 통과 → 태그 → 형제 저장소 알림
  • ADR로 결정 기록: 001 네이밍 · 002 Admin 블루 · 003 다크 정책

금지

  • main 직접 커밋 · dist/ 손 편집
  • "임시" 로컬 색 추가 (다음 릴리스에서 토큰으로 승격하거나 삭제)
  • 채용·캠페인 페이지를 DS 저장소에 호스팅
